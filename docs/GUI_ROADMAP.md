## 2. 当前 GUI 基线（代码事实）

### 2.1 实机截图证据（2026-03-22）

截图方式：启动 `build\Release\CrosECControl.exe`，用 Win32 `PrintWindow` 抓主窗口（**不是** browser computer-use；本程序为原生 Win32，`agent_browser`/Electron 模式不适用）。

| 文件 | 说明 |
|------|------|
| [`docs/screenshots/main-window.png`](screenshots/main-window.png) | 启动默认客户区（约 480×535，内容严重裁切） |
| [`docs/screenshots/main-full.png`](screenshots/main-full.png) | 调整到约 960×672 |
| [`docs/screenshots/main-screenfit.png`](screenshots/main-screenfit.png) | 铺满当前屏约 1128×712 |
| [`docs/screenshots/main-design-height.png`](screenshots/main-design-height.png) | 尝试设计高度；被工作区限制在约 980×767 |

观测环境：工作区约 **1128×752**。设计默认窗体 **960×1070**，在此屏上**无法完整显示**；无客户区滚动时，诊断区按钮只露出上沿或完全不可用。

截图可见问题（按严重度）：

1. **首屏裁切（P0）**：充电上限以下的“只读诊断与备份工具”在常见笔记本高度下被切掉；小窗时连风扇“自定义”和 RPM 都会裁切。
2. **布局不响应（P0）**：扩大窗口后上方区块仍绝对定位，空白被浪费，底部仍不够；`layout()` 基本只动输出框。
3. **层次扁平（P1）**：深色底 + 同色静态文本，概览指标缺少卡片/分隔；`kPanel` 色板未形成可视分区。
4. **状态弱提示（P1）**：“EC 已连接”为灰色普通标签，温度 63°C 无色阶；告警主要依赖托盘，主窗不够醒目。
5. **控件风格割裂（P2）**：Win32 经典 Trackbar（白槽/蓝拇指/刻度点）与自绘深色文案并存，精致度一般。
6. **信息重复与密度不均（P2）**：标题栏图标标题 + 客户区大标题重复；区块间竖向空隙大，但电池三行摘要又偏挤。
7. **窄宽溢出风险（P2）**：`F1 xxxx / F2 xxxx`、长充电说明在窄窗易截断（小窗截图已出现 RPM 被切）。
8. **主路径与诊断同级（P1）**：诊断按钮网格与主控同页竞争高度，加剧 P0 裁切。

### 2.2 代码结构

实现集中在 `src/main.cpp`，单窗口纵向堆叠：

```text
标题 / EC 状态 / 立即刷新
设备概览（温度、风扇、模式、电池摘要）
风扇控制（自动/关闭/最大/自定义 + 滑块）
键盘背光（滑块）
电池充电上限（滑块 + 应用/恢复）
只读诊断与备份（按钮网格 + 输出框 + 驱动备份/诊断报告）
ECTOOL 路径
```

已具备的能力：

- 深色主题色板（`kBg` / `kPanel` / `kAccent` 等）
- 异步 `ectool`、诊断输出、导出报告、驱动备份
- 系统托盘常驻、温度/断连气泡、工具提示
- Battery Sustainer 充电上限与风扇安全确认

当前主要结构性问题：

1. **绝对坐标布局**：`createUi()` 写死坐标；`layout()` 只拉伸诊断输出与路径标签。
2. **窗口过高**：默认约 `960×1070`，小屏/高 DPI 缩放后容易裁切。
3. **信息架构扁平**：控制区与诊断区同屏堆叠，主路径（看状态/调风扇）被诊断按钮挤占。
4. **视觉层次弱**：已有 `kPanel` 画刷，但概览区仍是平面标签，缺少卡片/分区背景。
5. **状态反馈不完整**：托盘有温度告警，主界面指标缺少颜色/徽章；命令执行中按钮禁用与进行中提示不统一。
6. **可扩展性差**：新增控件必须手改坐标与 `WM_COMMAND`，后续功能会继续拉长窗口。

## 3. 设计原则（后续迭代必须遵守）

1. **主路径优先**：打开窗口 3 秒内应能看清温度/风扇/电池，并完成风扇或充电操作。
2. **诊断次之**：详细 `ectool` 输出默认折叠、分页或次级区域，不与主控抢首屏。
3. **安全不弱化**：关闭风扇确认、退出恢复 `autofanctrl`、禁止高风险命令入口，均不可为“界面简洁”而削弱。
4. **继续原生 Win32**：可用 Common Controls（Tab、Progress、ToolTip、StatusBar）；不引入 Qt/WPF/WebView UI 栈。
5. **异步与线程模型不变**：UI 线程只更新控件；慢操作走后台 + `PostMessageW`；`gProcessMutex` 串行 `ectool`。
6. **小步可验证**：每一阶段都能单独 Release 构建，并在有/无 `ectool` 环境下启动验证。

## 4. 目标信息架构

```text
┌──────────────────────────────────────────────┐
│ 标题 · EC 状态徽章 · 刷新 ·（可选菜单）       │
├───────────────────────┬──────────────────────┤
│ 概览卡片              │ 快捷状态             │
│  温度 / 风扇 / 模式    │  电池% · 健康 · 功率  │
│  连接/告警条          │  充电策略摘要         │
├───────────────────────┴──────────────────────┤
│ [控制]  [诊断]  或  可滚动单页 + 折叠诊断      │
│                                              │
│ 控制页：风扇 / 背光 / 充电上限                 │
│ 诊断页：只读按钮 + 输出 + 备份/报告            │
├──────────────────────────────────────────────┤
│ 状态栏：ECTOOL 路径 · 上次刷新时间 · 忙闲     │
└──────────────────────────────────────────────┘
托盘：显示/退出 + 后续快捷操作（自动风扇、刷新）
```

推荐默认方案（改动可控）：

- **阶段 A**：仍单页，但分区卡片化 + 真正响应式布局 + 最小高度可滚动。
- **阶段 B**：引入 `Tab`（控制 / 诊断）或“诊断”折叠面板，把默认窗口高度压到常见笔记本可视区。

备选方案（更大改动，不作为第一优先）：

- 主窗口只保留概览+控制；诊断改为独立工具窗口。
- 托盘迷你气泡窗（hover 弹出温度/风扇）。仅在主路径稳定后再做。

## 5. 分阶段计划

### 阶段 0 — 基线冻结与度量（0.5 天）

目标：后续改布局时有对照，不靠感觉回归。

- [ ] 记录当前默认客户区尺寸、最小可操作分辨率、高 DPI（100%/150%/200%）截图基线
- [ ] 列出首屏控件清单与“必须始终可见”的 6 项：连接状态、最高温度、风扇 RPM、风扇模式、电池%、充电策略
- [ ] 在本文维护“已完成 / 进行中 / 放弃”变更日志
- [ ] 明确不在 GUI 迭代中做的事（见第 7 节）

完成标准：有可复查的截图或简短检查表；无代码也可先完成。

### 阶段 1 — 布局系统与小屏可用（高优先级）

目标：窗口缩放不再“只有输出框会动”，小屏可完整操作。

建议实现：

1. **引入简单布局辅助**（仍可留在 `main.cpp`，或抽 `src/ui_layout.hpp`）
   - 锚点：左/右/顶/底边距、宽高跟随
   - 垂直栈：按 section 计算 `y`
   - `WM_GETMINMAXINFO` 设最小宽高
2. **客户区滚动**
   - 高度不足时出现垂直滚动，而不是裁切按钮
   - 或降低默认高度并把诊断放入 Tab（可与阶段 2 合并）
3. **统一边距节奏**
   - 外边距 24–28、区块间距 16–20、控件高 36–44
4. **状态栏**
   - 将 `ECTOOL` 路径、最后刷新时间、后台忙闲移到底部 `StatusBar` 或固定底栏

完成标准：

- 高度 800 与 1200 下主控按钮均可达
- 宽度 900–1400 下标签不严重重叠
- Release 构建无新增警告

### 阶段 2 — 视觉层次与状态表达（高优先级）

目标：一眼区分“正常 / 告警 / 不支持 / 进行中”。

建议实现：

1. **分区卡片背景**
   - 使用已有 `kPanel` / `kPanel2` 自绘或静态帧
   - 概览三指标（温度/风扇/模式）做成等宽卡片
2. **指标着色规则**
   - 温度：`<70` 常态，`70–79` 提示，`80–89` 警告，`≥90` 严重（与托盘阈值对齐）
   - EC 未连接：状态徽章红色/灰色，控制区整体禁用
   - 充电不支持：滑块禁用 + 说明文案（已有，保持）
3. **Busy 态**
   - 刷新/命令进行中：相关按钮 `EnableWindow(FALSE)` 或显示“执行中…”
   - 诊断输出标题显示当前命令名（部分已有 `setOutput`）
4. **电池摘要增强（只读展示，不新开危险命令）**
   - 健康度、循环次数、功率、ETA 保持一屏可读
   - 可选：简易 progress bar 显示电量 %（Common Controls）

完成标准：

- 断连、高温、风扇 0 RPM 高温场景在主窗口有可见反馈（不只靠托盘）
- 无 `ectool` 时启动仍清晰显示“未找到/未连接”

### 阶段 3 — 信息架构收敛（中优先级）

目标：缩短默认窗口，强化主路径。

推荐路径（二选一，先做原型再定）：

**方案 3A — Tab 控件（更清晰）**

- `控制`：风扇、背光、充电
- `诊断`：只读按钮、输出、备份、报告
- 概览条始终钉在 Tab 上方

**方案 3B — 折叠诊断（改动更小）**

- 默认折叠诊断按钮区，只留“展开诊断 / 导出报告 / 备份驱动”
- 展开后显示完整按钮网格与输出

附加增强：

- 诊断按钮按任务分组：电池 / 接口 / 固件 / 传感器
- “导出诊断报告”提升为诊断页主按钮
- 复制输出保留快捷入口

完成标准：

- 默认首屏无需滚动即可完成风扇切换与充电上限调整（1080p、125% DPI）
- 诊断能力不减少

### 阶段 4 — 交互细节与托盘增强（中优先级）

目标：少点几下、少打断、状态可恢复。

- [ ] 托盘右键增加：`立即刷新`、`风扇自动`（退出外的快捷恢复）
- [ ] 工具提示：关闭风扇、充电迟滞 5%、自定义占空比说明
- [ ] 快捷键：`F5` 刷新，`Ctrl+C` 在输出聚焦时复制（注意与全局冲突）
- [ ] 充电上限预设芯片按钮：`60%` / `80%` / `100%`（100% = 恢复 normal）
- [ ] 记忆用户偏好（`%AppData%\CrosECControl\settings.json` 或 ini）
  - 窗口位置与大小
  - 上次充电上限草稿
  - 自定义风扇滑块值
  - 是否启动最小化到托盘
- [ ] 首次隐藏到托盘的提示只显示一次（已有 `gTrayHintShown`，可持久化）

完成标准：

- 偏好读写失败不影响启动
- 托盘快捷操作仍走确认/安全逻辑（自动风扇可直接执行；关闭风扇不要放托盘一键）

### 阶段 5 — 代码结构与可维护性（中低优先级，可穿插）

目标：GUI 继续长功能时不让 `main.cpp` 失控，但不为重构而重构。

建议拆分（按需，不必一次做完）：

```text
src/
  main.cpp          # WinMain / 消息泵
  app_state.hpp     # Snapshot、全局状态
  ui_theme.cpp      # 颜色、字体、刷子
  ui_layout.cpp     # 布局与 resize
  ui_controls.cpp   # createUi / 控件事件
  ec_commands.cpp   # ectool 定位、执行、解析
  tray.cpp          # 托盘
  backup.cpp        # 驱动备份
```

规则：

- 拆分后仍无第三方依赖
- 先抽无行为变化的纯函数（解析、格式化），再动窗口过程
- 每次拆分必须 Release 构建通过

### 阶段 6 — 可选探索（低优先级，需单独评估）

以下内容**默认不做**，仅在有明确用户需求时单独立项：

| 想法 | 价值 | 风险/成本 |
|------|------|-----------|
| 温度历史折线图（自绘/GDI+） | 好看 | 复杂度高，需环形缓冲与重绘策略 |
| 多风扇独立占空比 | 强力用户 | 设备支持差异大，UI 与安全确认更复杂 |
| 设置对话框（语言/刷新间隔） | 可维护性 | 要做持久化与校验 |
| 浅色主题 | 少数需求 | 全套色板与对比度回归 |
| WebView2/XAML Islands 美化 | 视觉上限高 | 违背轻量原则，不建议 |

## 6. 建议实施顺序（执行视图）

```text
0 基线 ──► 1 布局/小屏 ──► 2 视觉状态 ──► 3 Tab或折叠 ──► 4 托盘/快捷/偏好
                 │                │
                 └─► 5 抽离无行为变化代码（穿插）
```

若一次只做一个 PR/一次改动，推荐切片：

1. **PR1**：`WM_GETMINMAXINFO` + 全控件 `layout()` + 底栏路径  
2. **PR2**：概览卡片 + 温度/连接着色 + busy 态  
3. **PR3**：控制/诊断 Tab（或折叠诊断）  
4. **PR4**：托盘快捷 + 预设充电 + 设置持久化  
5. **PR5**：源码拆分（可空窗期进行）

## 7. 明确不做（GUI 迭代禁区）

与 [`AGENTS.md`](../AGENTS.md) 安全边界一致，GUI 迭代中禁止：

- 任意命令输入框 / 原始 `ectool` 终端
- 固件刷写、GPIO、I2C、EC reset、`batterycutoff` 等入口
- 主程序内驱动安装/恢复按钮
- 托盘一键“关闭风扇”
- 为美观引入重型 UI 框架或 Web 壳
